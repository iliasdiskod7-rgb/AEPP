# Αντιπαραδείγματα και AI review

Στην αναλυτική αναφορά κάθε προγραμματιστικού ερωτήματος υπάρχουν τα κουμπιά «Αναζήτηση αντιπαραδείγματος» και, για συνδεδεμένο χρήστη με διαθέσιμο API, «AI Code Review». Το feedback AI εμφανίζεται και χωρίς αντιπαράδειγμα. Δεν αλλάζει αυτόματα τον βαθμό.

## Προδιαγραφές εισόδων

Το προαιρετικό `fuzzSpecification` του ερωτήματος επαληθεύεται με Zod και περιέχει:

```json
{
  "scalars": [{"name":"Ν","type":"integer","min":1,"max":5,"role":"count"}],
  "arrays": [{"name":"Α","countVariable":"Ν","minLength":1,"maxLength":5,"min":-100,"max":100}]
}
```

Οι τύποι scalar είναι integer/real/string/boolean. Υποστηρίζονται επιτρεπτές τιμές `allowed` και ρόλοι value/count/searchKey. Τα όρια scalar εφαρμόζονται σε κάθε ανάγνωση της αντίστοιχης μεταβλητής ή κελιού πίνακα. Οι πίνακες εισόδου για ταξινόμηση/μείωση μήκους είναι μονοδιάστατοι· μπορούν να έχουν περιορισμό `sorted: ascending|descending`. Πρόσθεσε τους πραγματικούς περιορισμούς της εκφώνησης, όχι περιορισμούς που συνάγονται από λίγα παραδείγματα.

Χωρίς προδιαγραφή, οι δοκιμές είναι διερευνητικές και η αναφορά το δηλώνει. Η συσχέτιση πλήθους–πίνακα γίνεται τότε μόνο με ευρετική γνωστών ονομάτων Ν/N/ΠΛΗΘΟΣ. Με προδιαγραφή, η αλλαγή μήκους απαιτεί ρητό `countVariable`. Μη έγκυρες είσοδοι, αποτυχία της πρότυπης λύσης και λανθασμένη κατανάλωση εισόδων της πρότυπης λύσης δεν αποτελούν αντιπαράδειγμα μαθητή.

## Εκτέλεση και ελαχιστοποίηση

Το `counterExample.worker.ts` συντονίζει δύο ανεξάρτητους, επαναχρησιμοποιούμενους Workers που εκτελούν μαθητή/πρότυπη λύση παράλληλα για την ίδια είσοδο. Ο κοινός generator αλγόριθμος οδηγείται ασύγχρονα στον browser και συγχρονικά στα unit tests. Τα edge cases καλύπτουν μηδέν, αρνητικούς, μεγάλους αριθμούς, δηλωμένα όρια, ταξινομημένους/αντίστροφους/όμοιους πίνακες και στόχους πρώτης/τελευταίας θέσης ή απόντος στοιχείου.

Πρώτα μειώνονται στοιχεία/πλήθος του πίνακα και μετά απλοποιούνται αριθμητικές τιμές προς 0/±1/μισό. Κάθε αποδεκτή μείωση διατηρεί τους περιορισμούς και τη διαφορά με έγκυρη πρότυπη εκτέλεση. Πρόκειται για περιορισμένη τοπική ελαχιστοποίηση, όχι εγγύηση παγκόσμια ελάχιστης εισόδου. Η αλλαγή κώδικα/ερωτήματος ακυρώνει τους Workers και την εκκρεμή κλήση AI. Έως 200 συγκρίσεις, 10 αρχικά σενάρια, 2 δευτερόλεπτα ανά εκτέλεση και 30 δευτερόλεπτα συνολικά. Η απουσία αντιπαραδείγματος δεν αποδεικνύει ορθότητα.

## Debugger

Το «Άνοιγμα στον Debugger» μεταφέρει αντίγραφο του κώδικα και των εισόδων μέσω App → InterpreterWorkspace → DebugInputBuffer. Οι είσοδοι προτείνονται με τη σειρά στη ΔΙΑΒΑΣΕ και ο μαθητής επιβεβαιώνει κάθε τιμή. Το Step Back επαναφέρει και τον δείκτη του buffer βάσει του ιστορικού εισόδων του DebuggerEngine.

## Review API

`POST /api/code-review`, JWT Bearer, σώμα `{ studentCode, metrics: { comparisonsCount, assignmentsCount, loopIterations } }`.
Απόκριση `{ efficiency, algorithmicRisks, styleAndAeppRules }`, με ελληνικό κείμενο και όριο 1200 χαρακτήρες ανά άξονα.

Ο controller απαιτεί Authorize και AiInsightsPolicy: κοινό όριο με Assessment Insights 5 αιτήματα/60s και 2 ταυτόχρονες κλήσεις ανά χρήστη. Το σώμα περιορίζεται σε 64 KiB, ο κώδικας σε 12.000 χαρακτήρες, κάθε μετρικό σε 0–10.000.000. Κατάσταση 429/502/503/504 αντιμετωπίζεται με φιλικό σφάλμα χωρίς εσωτερικές πληροφορίες από την εξαίρεση.

Τα μετρικά μετρούν πραγματικές συγκρίσεις, εκχωρήσεις (περιλαμβάνεται ΔΙΑΒΑΣΕ/επιστροφή παραμέτρων) και εκτελεσμένα σώματα βρόχων του συγκεκριμένου run. Ένα swap περιλαμβάνει τις εκχωρήσεις του· δεν υπάρχει ξεχωριστός μετρητής swaps. Τα δεδομένα από client δεν χρησιμοποιούνται ως αξιόπιστη βαθμολογία ή απόδειξη ασυμπτωτικής πολυπλοκότητας. Το prompt αντιμετωπίζει τον κώδικα ως δεδομένα και ζητά τεκμηριωμένες, υπό όρους προτάσεις.

Έλεγχοι: `node --test tests/counterexamples.test.mjs tests/assessment.test.mjs tests/debugger.test.mjs`, `npm run build`, και .NET `AeppGenerator.Checks` με fake Gemini transport. Πραγματική κλήση Gemini απαιτεί τις ήδη υπάρχουσες ρυθμίσεις LlmSettings στο backend.
